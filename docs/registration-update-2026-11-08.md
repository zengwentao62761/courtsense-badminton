## 可复制的进展补充

我补充一下羽境CourtSense的最新进展和本次参赛计划。项目地址：https://github.com/zengwentao62761/courtsense-badminton 。原RDK部署工程保留在Codeup，CourtSense是当前主要开发、对外展示和参赛迭代的独立项目。

已有基础分为两部分。前序工程在RDK X5和单目MIPI相机上部署过人体姿态服务，实现17点骨架、二维关节角和训练工作台；历史短时验证约13 FPS，并已实际通过VS Code Remote-SSH进行板端开发，使用Git和Codeup保存版本。小规模QLoRA、适配器合并、GGUF量化和X5 CPU推理也有实验记录，属于链路试跑，当前不能支持可靠实时动作评分。

新项目已发展到P0.2.0，包含训练概览、标定与跑位、球迹与击球、报告与设备四个工作区。手动点对标定、接地确认点的米制映射、二维/显式三维球迹导入、候选与确认扣杀事件去重、按真实时间计算像素速度及条件化三维估计速度已有可运行基础，并支持输入、结果和来源导出。11月6日开发验证记录包含39项本地测试及浏览器操作检查。这些专项能力目前使用手工或导入数据；自动识别与真实场地精度待补充。

另外，Windows CPU已对公开比赛视频20秒片段完成100抽样帧的姿态处理、画面展示与HTML/JSON报告，相关来源和方法已写入仓库。它证明真实视频处理链路跑通，不作为球场定位、扣杀识别、真实球速或RDK性能的结论。公开仓库提供自制合成开发样例及清晰标识，未直接分发比赛转播画面。

本次现场重点是把软件基础接到实际的RDK与训练装置上。先做固定机位、人工确认场线、独立控制点测量与单人位置验证，再逐步接通三个关键扩展：移动底盘负责训练前停靠及停车后重定位；云台负责主动观察、机位复现与停稳锁定；球拍IMU负责带原始采样时间的候选挥拍，与视频建立可检验的时间对齐关系。训练时底盘停止、云台锁定，机位变化后重新检查标定。

最小演示拟采用中点、左前、右前三个训练区：实体提示目标，视觉确认到位与回中，再给下一轮任务；IMU接通后加入候选挥拍条件。验收保留连续十轮任务、未回中不推进、遮挡等待、设备断连停止和可回放证据。固定支架模式先跑通，移动停靠和主动观察按实际进度增强；自动捡球和机器人持拍发球不作为首个闭环的依赖。

产品长期面向教练管理多片球场的使用场景，探索4—6片场地的成本分摊。手机App或小程序、本地集中分析是后续候选路线，尚未定型。建议近期先接手机端配置和报告入口，后续独立测试手机本地视觉及一机多路；不预先宣称并发路数、手机FPS或已经实现降本。

算法区分远景全场与近景专项：远景研究跑位、起跳和击球事件；近景研究可见的拍—腕关系和动作阶段。我们已与体育老师合作，对方有训练教学视频，拟在取得适用授权后按章节整理示范、阶段和教师确认的要点，再将学员证据与章节关联。专业评价标准由老师参与制定与复核，不直接把通用大模型回答当作标准评分。
