# 技术方案与关键问题

阶段：P0.2.0。仓库已有手动点对拟合、接地确认米制映射、球迹与扣杀事件导入及条件化速度计算，见[分析开发指南](analysis-development.md)。本页的自动场线/球体检测、扣杀分类、实测精度与实体控制仍待验证或实现。下一阶段关键扩展为移动底盘、云台、球拍IMU，详见[三设备设计](embodied-expansion.md)。首版训练采集保持单人固定机位，设备运动安排在训练前或暂停后。

## 1. 球场有划线，为什么不直接用SLAM

球场是带有已知几何与语义的平面地图。固定相机首先需要的是相机与这张地图的对应关系，而不是用相机运动从零恢复未知地图。可借鉴SLAM中的地标关联、鲁棒优化、状态估计、重定位及不确定度表达，但不宣称固定机位系统已实现SLAM。

拟建立球场线拓扑图：边界、单打/双打边线、发球线和交点带有不同语义。按适用BWF图示建版本化米制模板；单双打使用不同有效边界，图示线宽与边缘/中心定义保持一致。标准模型只提供先验，现场仍核验尺寸、缺损与非标准练习场。

流程：标定固定焦距镜头内参与畸变；提取线段和交点；人工确认至少四个空间分布充分的非共线对应点，优先用更多线/点；排除相邻球场、篮球线及左右对称误配；RANSAC与线/点联合优化平面单应。保留人工确认与自动候选来源。若需要三维球轨，再结合内参求相机外参，并利用相机位于地面上方、实际机位和重投影排除镜像解。

检测场线在后续帧中的漂移，持续检查投影残差。相机被碰动、变焦、裁剪或电子防抖改变成像关系时，暂停米制输出并重新标定。稳定相机无需每帧重跑全套建图。三维球场渲染是模板可视化，不能冒充真实三维扫描。

验收不能只看参与拟合的角点：另布置卷尺测量的独立控制点，在近、中、远区域测误差，并分别报告中位数、P95、覆盖率与失败情况。阈值在首批现场采样后定，不提前承诺厘米级精度。

## 2. 不用深度相机，如何定位球员

去畸变图像中的可信地面接触点可通过单应映射到球场。结合人体跟踪、足部/踝点可见性与时序接触判断，选择支撑脚或明确约定的双脚站位代理；COCO17只有踝点，并不天然提供脚底接触，需要专门验证，必要时增加云端足部模型或人工参考。

不把髋中心、人体框底部、离地踝点直接当作真实地面位置。两脚腾空、遮挡、出画或身份不确定时输出缺失；短段预测和插值单独标记。身份跟踪先限制单人，后续需单独验证多人交换和遮挡。

输出单位包括米制可信点、区域归属、位置置信度和标定版本。热图按真实时间间隔累计停留时间，不能按云端处理帧数计时；测量轨迹与补全轨迹分层，跑动距离对抖动和缺失段做专项验证。地面定位精度不代表人体三维关节精度。

## 3. 扣杀次数如何统计

先检测逐次击球候选，再融合人体序列、持拍侧、球拍信息与击球前后羽毛球轨迹，区分扣杀、高远球、吊球、挥空等。下行的二维球迹或高举手臂都不足以单独证明扣杀。首版允许候选扣杀、人工确认、无法判断三种状态。

事件具有唯一ID、球员ID和时间范围，合并同一击球的多个候选帧，避免逐帧累加。使用独立比赛/场次划分标注数据，按事件报告precision、recall、F1、重复/漏计与每段计数误差。动作类别标签不等于技术质量分。

## 4. 羽毛球检测与轨迹

羽毛球是高速小目标。先审计实际传感器模式、分辨率、曝光、视场、时间戳、压缩、丢帧与存储带宽，再决定可观测能力。曝光不足、严重拖影或球已落在像素分辨率以下，上传云端也无法恢复真实细节。

参考TrackNetV3的多帧检测思路，在云端验证对本机位的迁移效果。区分球头/球体检测点定义，对背景白点、球拍和灯具作负样本标注。缺失轨迹补全要带标志，不能伪装成已检测结果；分割每次击球之间的飞行段。

最先交付像素坐标下的二维轨迹及可见性，之后再研究三维。飞行中的球不在球场地面，不能通过地面单应直接得到其真实三维坐标。

## 5. 时速能不能算

像素轨迹除以真实帧间隔，只得到像素速度。地面映射不能让空中球自动获得真实米制速度。

单目每个观测对应一条空间射线，存在深度歧义。研究路线是：已标定的相机、真实时间戳、击球/落点等有证据的边界条件，以及重力与羽毛球显著空气阻力模型，联合拟合分段三维轨迹。羽毛球不能简单套用无阻力抛物线；落地时间、击球高度等先验也要区分实测与假设。

只有轨迹约束足够、解稳定并经过独立参考验证的片段才显示估计速度及误差范围，否则不显示km/h。分清平均飞行速度、某时刻瞬时速度与离拍初速，禁止把长片段平均速度宣传成扣杀最高速度。短时间初速尤其依赖高帧率、短曝光和参考测量；云GPU不能替代采样。

MonoTrack提供单目球场、人体、球轨与物理约束的相关研究先例，但不保证能直接迁移到现有MIPI机位。无深度相机不等于无需标定或独立参考；如需验证，可在受控实验借用测速设备或经过测量验证的参考系统，参考不作为产品日常部署依赖。

## 6. 球拍、手腕与动作评分

COCO17没有手指、掌面与球拍关键点。先增加云端球拍头/柄和手部关键点标注，定义拍柄方向、前臂方向与动作阶段。二维拍柄—前臂可见夹角可以作为特定视角描述量，不能直接等同真实腕关节三维屈伸、握拍规范或发力大小。

评分需教练制定按动作阶段、持拍侧与机位适用的标准，并检查标注一致性。先输出有证据的检查项和片段，参考不足时不输出总分。不把骨架平滑、动作分类概率或球速单项包装成综合专业等级。

## 7. 端云协同与实时性

端侧保留现有采集与必要人体感知，新模型优先云端。原MIPI采集进程是唯一相机所有者，采集扩展需单独审计接口和部署，不再另开相机进程。保留原始/高质量素材、视频PTS、单调采集时间、序号和会话ID；不同降采样分支可追溯原帧。

采用本地环形缓存与断网续传；原视频、低延迟预览、事件分析是不同质量/带宽档。不能用现有低帧率压缩预览代替高速球轨采集。运动模糊、滚动快门和编码损失均单独记录。

区分端侧采集延迟、传输、队列、云推理、回传与展示的端到端延迟。先做离线与准实时回看，基线采样后再给实时目标；不得只报模型推理时间。显示事件发生时间、结果到达时间和数据龄期，过期反馈不进入物理控制。

## 8. 三项关键具身扩展与候选创新

移动底盘负责训练前停靠与视觉重定位；云台负责场线主动观察、停稳和机位复现；球拍IMU负责带原始时间的候选挥拍。共用空间变换链、时钟域和会话版本，实际任务与验收见[扩展清单](extension-tasks.md)。IMU不直接证明触球或扣杀，底盘尚无自动捡球能力。

建立以球场为坐标的人—球—拍时空记录，根据可信跑位、回位及事件选择练习，通过MCU声光或固定柔性靶改变训练任务，用真实到位或触靶反馈决定下一轮。尚无执行器时明确称视觉分析系统。

保留假动作对抗作为独立研究模式，使用中性名称“羽境·影子对抗”。继承隐藏目标、预测截止时间、机构实际到位及人工/自动结果区分，不将游戏胜负当作预测准确率。

候选研究贡献包括：球场线语义与人体接触约束的联合可信定位；稀疏高速小目标下带不确定度的事件和轨迹融合；依据观测质量选择补测与训练任务。都需与已有方法比较，不宣称全新算法或专利新颖性。
